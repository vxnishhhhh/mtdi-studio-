## Features
- **Third Eye (`projects/third-eye`, S1-07)**, MTDI 1 rebuilt on MTDI 5:
  - left and right HC-SR04 rangers, in cm, plus the buzzer state, Edge profile;
  - the studio shows "Left distance" and "Right distance" in cm;
  - three NVTRA rules: something on the left, something on the right, something ahead on both sides;
  - the firmware (`firmware/third_eye/third_eye.ino`) compiles for the Uno with arduino-cli: 5,712 B flash, 257 B RAM;
  - the buzzer beeps faster as something gets closer and holds a steady tone under 20 cm;
  - when a ranger hears no echo, it leaves its key out of the line, so MTDI records a gap instead of a made-up distance.
- **NVTRA `direction` (new, every project):**
  - a rule can say `"direction": {"left": "down"}`, which means the reading must be below the baseline it learned, or `"up"` for above;
  - `mtdi check` rejects an unknown channel, a value other than up or down, and vector channels;
  - documented in `docs/MANIFEST.md` and the schema.
- **Studio labels for fed data (#49):**
  - when an MTDI project feeds the studio, channels 1 and 2 name the sender (for example "MTDI:third-eye") instead of the studio's own sensor addresses (0x2C, 0x48);
  - simulated data says SIMULATED DATA, in amber;
  - the SOURCE LINK card does the same.

## Bugs found and fixed
- **Channel 2 crash (on main before #49).** `update_ch2f_numbers` raised UnboundLocalError for any channel 2 data that did not come from the Uno, which covers every MTDI project and every `/api/ingest` post.
- **Third Eye said "something on the left" when the left wall moved away.** NVTRA compares the signal-to-noise ratio, which has no sign. A distance going from 150 to 260 cm matched the same rule as one going from 150 to 40 cm. CodeRabbit flagged it and I reproduced it. The fix is the `direction` field above, so the engine is fixed rather than the wording.
- **The buzzer held NVTRA at "Baseline settling" forever** (found before the PR). I had given the 0/1 buzzer state `raw_range [0, 1]`, so every sample counted as clipped and the baseline never formed. I removed it, and MANIFEST.md now warns about on/off channels.
- **One simulated slot made every slot SIMULATED over HTTP.** A hardware reading pushed over HTTP was labelled SIMULATED whenever a simulated slot was in the same push. Each label now goes in its own request.
- **A failed push lost its readings.** The bridge marked a sample as sent before it was delivered, so if the studio was restarting, that sample was never resent. This was on main too. Samples are now marked only after delivery, and HTTP sends one request with a label per sample, so it lands whole or retries whole.
- **"SIMULATED" anywhere in a name turned the label amber.** A real project called, say, `SIMULATED-annealing-rig` was shown as simulated. Only a leading `SIMULATED` counts now.
- **Stale labels after a switch.** After a feed, the studio's own sensors kept the fed sender's name. After an Uno reading, a feed kept the Uno's status and frozen axis values. Both are now reset.
- **Wrong rate.** The Third Eye manifest said 15 lines a second. The firmware's real cycle gives about 13, and about 9 when both rangers time out. It is now `expected_rate` 12.

## Ideas
- **A replay for Third Eye.** One real 5-minute recording on hardware closes S1-07, and the universality test (S1-09) can then replay it in CI with no board.
- **Make `alert_change` do something, or remove it.** It is in every manifest, Third Eye's included, but nothing in `mtdi/` or `studio/` reads it (see Weaknesses). If it becomes a real alert threshold, it should take a `direction` too, so a project can alert only on a drop (a falling tank level) or only on a rise.
- **Compile every firmware in CI.** arduino-cli works here through the proxy, so the Compatibility Lab workflow (S1-05) can compile every sketch in `projects/*/firmware`, not just Third Eye.

## Struggles
- **CodeRabbit caught a logic flaw I shipped.** I tested "closer" and never tested "farther", so the direction bug passed 9 of my own tests. New rule for myself: for every rule that names a direction, test the opposite direction too.
- **arduino-cli needed two settings to get past the sandbox proxy** (`ARDUINO_NETWORK_PROXY`, `SSL_CERT_FILE`), and GitHub release downloads return 403 here. It works now, but only in this session. CI needs its own install step (S1-05).

## Weaknesses
- **No firmware has run on a real board in this repository.** Third Eye compiles. Nobody has flashed it, so the timing, the echo timeout and the buzzer pattern are all unverified.
- **No recording yet.** S1-07 stays "in progress" until a real session exists. I won't fake one.
- **Stale charts after a source switch.** After a fed reading, the triaxial channel 2 charts keep showing the Uno's history. The numbers reset and say "0 / 3 axes", which is honest, but the charts keep the old trace.
- **`alert_change` does nothing.** The manifest field gets a default (20 × the noise floor), but no code reads it, so writing it in a manifest has no effect. I found this while writing this report and haven't fixed it yet.
- Still open from yesterday: the Pi, Mac and real-phone checks; 128 channels still take over 100 ms per snapshot in the cloud.
