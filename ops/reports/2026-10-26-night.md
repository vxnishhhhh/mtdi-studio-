## Bugs found and fixed
* **A 500 on the page from two callbacks computing at once (#65).** The tour on #64 hit `deque mutated during iteration` in `studio/d4live.py`. That bug was already there and #64 didn't cause it. `snapshot()` released its lock while computing, so two Dash callbacks could compute the same packet together: one read a history list while the other was adding to it. Computations now run one at a time, and a caller that waited reuses the packet just computed. A test of 8 simultaneous calls ran 8 computations at once on the old code; now it runs one.
* **The fix itself had two holes (CodeRabbit, #65).**
  * The packet was published after the lock was released, so an older packet could overwrite a newer one.
  * The Major one: reusing a packet that finished while a caller waited meant a config reload could be undone. A forced snapshot, such as recording a reference profile, could save features computed with the old config. The reload now waits for any computation in flight, and a test reproduces the old failure.
* **My chart words said things the code doesn't know (CodeRabbit, #64).**
  * A quiet sweep claimed "no new energy" before that check had run. It needs 6 sweeps; the message now says so.
  * The IQ path's colour bar said µs but showed amplitude.
  * The constellation's colour bar said "samples" but showed log10(samples + 1).
  * Wi-Fi dBm derived from link quality wasn't marked approximate on the charts.

## Ideas
* **A soak test in CI.** The race only showed up because the tour happened to fire two callbacks together. Running 20 parallel requests against `/_dash-update-component` for a minute in CI would catch this class of bug on purpose, not by luck.
* **Check what every colour bar shows.** Two of my mistakes were colour bars labelled with the wrong quantity. A test could assert that each colour bar's title matches the quantity its trace is coloured by.
