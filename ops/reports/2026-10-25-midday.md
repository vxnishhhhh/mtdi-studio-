## Features
* **An upright swipe no longer leaves the studio (#58).**
  * The bug: holding the phone upright, a swipe during the intro or inside any scrollable panel was taken by Chrome as "swipe back", and the tab went blank. This was live from #55 until 11:22 UTC.
  * The fix: nothing in the turned stage pans by itself now. The `/phone` shell does all the scrolling, including text boxes that have overflowed.
  * Checked against the live site before and after: before, the first upright swipe in the intro → `about:blank`; after, the intro and Page 1's opening each clear in 2 swipes, then the page scrolls.
* **Swipe pass in the tour (#58).** It runs upright with motion on and sends timed touches at 60 Hz. It fails on a swipe-back, on an opening that takes more than 3 swipes, or on a page that doesn't scroll afterwards. It runs in its own full-Chrome browser, because headless Chromium has no swipe-back, which is why every earlier emulator run missed the bug.
* **NVTRA's island on a phone (#58).** The idle hint says "Tap ◍" on touch screens instead of "Press ◍ or N". On the phone stage, the idle island sits in the bottom-right corner, where it no longer covers the bottom title button on Home.

## Struggles
* **I shipped the swipe-back bug in #55 and didn't see it for a day.** Every emulator run used headless Chromium, which has no swipe-back. Rule for myself: phone checks run in full Chrome as well.
* **I misread the cause at first.** I tried `overscroll-behavior` first, and it did nothing. The real cause: `touch-action` only reaches up to the nearest scrollable box, so the root's `none` never applied inside the intro.
* **My background check waited on itself.** It looked for the tour process by name, and its own command line contained that name. I stopped it and read the result directly. The scratch-script lesson: wait on a process ID, not a name.
