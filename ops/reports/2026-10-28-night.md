### Features
* **The analysis engine names channels in the project's words.** Its alerts, evidence lines, warnings and channel cards used to say "Channel 1" to "Channel 4". Channels 1 to 3 now take their names from the content file, and the coil current channel is "Current".
* **The engine's default units are real.** They are now µT, mV RMS relative, dB and A, the units of the studio's own sources. Before, three were the placeholder "unit". Channel 1 calibration accepts µT or uT and defaults to µT.

### Bugs found and fixed
* **The studio's own magnetometer reported its readings in "unit".** Both acquisition paths fed the engine the literal unit "unit", left behind by the rename pass, though the readings are converted to microtesla on the way in. So every channel 1 alert ("… rose 3.2 unit from its quiet baseline"), evidence line and Page 3 card said "unit" where it meant µT. Both paths now say µT.
* **A channel 1 feed that named no unit was labelled "unit".** This applied to /api/ingest and `feed_ch1` called without one. Such a feed now reads in the project's channel 1 word. It is never labelled µT, because it was never converted to microtesla. This is the same rule `ch1_value_unit` already used for the cards.
* **The axis panel always reported its unit as "unit".** It now reports the channel's own unit.

* **CodeRabbit on this PR: 2 findings, both fixed.**
  * The calibration form's channel switch reset channel 1's unit to "unit", which this slice now refuses. It now resets to µT. The bug dates from the rename pass and became a refusal here.
  * A calibration that named no unit took the studio's physical unit (µT for channel 1) even on a project feed in cm, so the feed's values would then read as magnetic. The engine now records each reading's source unit. A project feed calibrates in its own unit, and that unit is accepted. The studio's own sources keep their physical defaults (the probe still calibrates to V/m), and an unrelated unit is still refused. tests/test_calibration_units.py covers all four cases; it fails without the fix.

* **CodeRabbit's second pass: 4 findings, all fixed.** My first fix guessed that a project feed was any source whose unit differed from the studio default. That guess was wrong for the Uno, whose "ADC counts RMS relative" made it look like a feed. Calibration profiles also weren't tied to the source they were made for. The root-cause fix:
  * `feed_ch1` and `feed_ch2` now mark their samples as fed, so the engine knows a project feed from the studio's own sources. The Uno probe keeps its V/m calibration default.
  * A calibration profile records the input unit it was made for. The engine skips it for samples in a different unit, so a cm feed's calibration never rescales or relabels the magnetometer when it comes back. Profiles saved before this change have no input unit and apply as before.
  * The calibration form's channel switch uses a fed channel's own unit, and falls back to the studio's units otherwise.
  * The axis panel shows the unit its values are in.
  * tests/test_calibration_units.py now has six cases, including the Uno and the magnetometer returning after a feed calibration.

### Tests
* The words test checks the engine's channel labels against the project's names. It checks that a channel 1 feed without a unit reads in the project's word, and it checks the engine's default units. On main, the label check fails ("Channel 1" for the project's name).

### Struggles
* **CI went red on the first push.** `run.py --self-test` asserted that the channel 1 unit was "unit". The self-test was pinning the placeholder this slice removes. I ran the unit suite before pushing but not the self-test. It now expects µT. All three CI steps (unit tests, self-test, project manifests) pass locally. From now on I run all three before each push.

### Next steps

### Weaknesses
* **Channel labels are read when the engine is built.** A content file changed while the studio runs is picked up only on restart. That is the same as every other word in the studio.
* **Current has no project word.** The content file has no key for it, so it stays "Current". That is honest for the studio's coil, and a project has no fourth channel to name.
