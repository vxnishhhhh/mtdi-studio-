# Rules for AI agents working in MTDI Studio

You are working on MTDI 5.0. Read `README.md`, then `INTEGRATING.md` before changing anything.

1. **Projects are manifests.** To integrate a project, write `projects/<id>/project.json` (and
   firmware or a sender if needed). Do not add project-specific code to `mtdi/`.
2. **Pillars stay universal.** Code in `mtdi/pillars/`, `mtdi/core.py` and `mtdi/engine.py` must
   never name a specific sensor, unit or project. Everything specific comes from the manifest.
3. **Never invent data.** No made-up readings, calibration constants, noise floors or results.
   Unknown values stay at defaults and are written down as unknown in the project README.
4. **Simulated stays labelled.** Anything from the simulator is `SIMULATED` end to end. Never
   remove that label, never record it, never save it as an environment.
5. **Other repositories are read-only.** Inductra Vaion lives in its own repository. Do not
   change it from here; `projects/inductra-vaion/firmware` and `bridge/` are byte-identical
   copies guarded by `tests/test_mtdi.py`.
6. **Verify before claiming.** Run `python -m mtdi check <project>`,
   `python -m mtdi run <project> --simulate`, and `python -m unittest discover tests`. Report
   failures as failures.
7. **I³ is a pillar.** The interface lives in `mtdi/pillars/i3/`. Pages are generated by
   `mtdi/studio/views.py` from the manifest; extend the generator, not individual projects.
